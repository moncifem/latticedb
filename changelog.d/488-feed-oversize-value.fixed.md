An oversize row value can no longer stop the change feed for every reader (issue 488): the row store refuses a put whose value is over the feed's 16 MiB bound with `RowError::ValueTooLarge` (SQLSTATE 54000 in SQL; one shared constant, `rowops::MAX_VALUE_BYTES`), deletes are unchecked, and for a value already in a log under a larger bound the feed delivers the events before it and gives only readers who may read that row `FeedReadError::ValueTooLarge`, after which reading again from its cursor skips it. Today the log's record limit equals the value bound, so no such value can be committed at all; this keeps the feed total if that limit grows. No bytes change.
