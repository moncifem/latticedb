`lattice watch` no longer stops for good when the gateway closes an idle connection with code 1008 and the reason "timeout". That close is now retried from the saved cursor with the usual backoff, and the watch says the connection timed out instead of blaming the token. It still stops at once when the token no longer verifies (reason "credential no longer valid"), and when the gateway speaks no protocol version the client speaks (reason "refused"); that second case is reported as an incompatible server. Not done: the gateway still uses 1008 for all three cases, so a client cannot tell them apart by code alone.
