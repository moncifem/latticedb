Human controls in the console: `lattice-console serve --allow-writes` adds an Inbox of what needs a person (tasks waiting for approval, dead letters, claimed tasks whose agent went quiet, tasks blocked for good, each with its text and last events) and approve, reject, cancel, requeue, priority and note, plus bulk cancel and requeue with a dry-run count (no bulk approve, no approval on a timer). Every decision is one `board act` call run as `human.NAME`: a new helper command that changes the task, writes an event and a `human_actions` audit row (who, what, comment, the sha-256 of the text that was approved) in one transaction. The person who produced a task cannot approve or reject it, an approval of text that changed after it was shown is refused, reject and note need a comment, and a repeated request id is a no-op; the `human.` names are refused by every other command. Writes are off without the flag (every POST is a 403) and need a per-run token printed once and sent in a header, an exact Origin and Host, strict JSON and a lockout after wrong tokens; the Content-Security-Policy is unchanged. `lattice-console serve --demo --allow-writes` simulates the decisions in memory. Names are self-declared, so one person under two names is two people, and anyone with the token or the database account can decide; the board account needs a grant on the new `human_actions` table.
