SDK outbox (#448): a batch is now bounded by its encoded `append` line, not only by record count. `poll` stops before the line would pass 1 MiB (counted with the longest request id, session id and turn, so five 256 KiB bodies go out as batches of 3 and 2), `enqueue` refuses with the new `OutboxError::BodyUnsendable` a body whose escaped line cannot fit alone (a 256 KiB body of control characters escapes to about 1.5 MiB), and `from_bytes` refuses a stored queue holding one. Before, the server refused the whole line, sent no receipts and the identical batch was resent forever, blocking every write behind it. The wire contract is unchanged, so the conformance vectors are too. New public items: `contract::APPEND_ENVELOPE_MAX_BYTES` and `contract::append_record_len`.
