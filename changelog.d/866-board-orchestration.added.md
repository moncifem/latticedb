Board orchestration: `board claim` takes a lease on the database clock with a fence token, and `heartbeat`, `note`, `done`, `fail` and `release` are refused (exit 3, recorded as a `fenced` event) when the lease was lost and the task re-claimed. `board fail` and expired leases retry with a backoff and end in a `dead` state after `max_attempts`; `board reap` expires dead claims; `board block` adds dependencies (a cycle is refused); `board next` claims the best runnable task (exit 4 when none) and `--needs-approval` plus `board approve` add a human gate. A second `board done` is now a no-op instead of an error, and `done` on a task another agent holds is refused. The lease columns live in a new `task_leases` table because the alpha runs no `ALTER TABLE`; `board migrate` adds rows for older tasks. The board console has a Queue screen and three new attention items (expired leases not reaped, dead tasks, tasks blocked for ever). The helper retries a failed connect on a few transient messages (the alpha.1 server drops some new connections, #867), runs every `psql` with `-w`, and its `test.sh` can run against an existing server (also run by the `dev-stack` CI job) (166 of 166 checks passed against the published alpha.1 image; not yet run against `main`). Not done: a timer (a lease expires only when a client runs `reap` or `next`), enforcement of who may approve (names are self-declared), an exact per-agent cap across processes that share a name, and a CI run of the real SQL against a `latticed`.
